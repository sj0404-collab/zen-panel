# TESTING.md — что нужно провести

Полный план проверок zen-panel: что уже ловится автоматически, что нужно
прогнать руками, и какие поломки известны прямо сейчас.

Документ описывает **проверку**, а не разработку. Каждому пункту дан ID
(`T-xx`), чтобы результат можно было отметить и не потерять.

### 2.3 Чего в автоматике нет

- `tools/open_tunnel.sh` и `tools/tunnel_health.sh` — **никаких тестов**. Туннель
  и Error 1033 проверяются только L3.
- Клиентская половина терминала (`term-app.js`) покрыта инвариантами исходника,
  а не поведением: `xterm` требует DOM. Настоящая проверка переподключения —
  T-51/T-52 на живом раннере.
- `tools/publish_session.sh` покрыт косвенно (`work-backup-test.sh`), но
  конкурентный пуш двух писателей (слот `linux` против `windows`) — нет.
- APK-сборка проверяется только на GitHub (сборщики), локально не воспроизводится.
- Нет проверки, что gate действительно включён на живом сервере (§4, F-08).

## 4. Известные поломки и риски

| ID | Что | Где | Влияние | Статус |
|---|---|---|---|---|
| F-01 | `publish_session.sh` пишет слот `vnc` в `live/session-vnc.json`, а `server.js` читает `session-vnc.json` **из корня** | `tools/publish_session.sh:104` vs `npm-hub/src/server.js:3111` | адрес noVNC не находится; работает только на легаси-файле, который никто не обновляет | открыто |
| F-02 | `hub-apk.yml` собирается только по путям `hub/**`, `settings.gradle.kts`, сам workflow. Правки `npm-hub/**` его не триггерят | `.github/workflows/hub-apk.yml:6-11` | сервер починен, а APK с оболочкой не пересобран | открыто |
| F-03 | `panel-apk.yml` заморожен на push (FROZEN by user request) | `.github/workflows/panel-apk.yml:3-14` | APK панели только вручную | по замыслу |
| F-04 | Общая concurrency-группа `zen-panel-session-${{ github.repository }}` у `agent`/`desks`/`hub`/`opencode`; GitHub отменяет **pending**-run при новом dispatch | 4 workflow'а, `concurrency:` | в журнале 20+ подряд `cancelled` | открыто (решение — за владельцем) |
| F-05 | Run'и без единого job висят по 23 мин и 2ч24м, затем отменяются | журнал run'ов | похоже на лимит параллельных job'ов аккаунта, не дефект workflow | наблюдение |
| F-06 | `tunnel_health.sh`, `open_tunnel.sh` без тестов | `tools/` | туннель ломается только в проде | открыто |
| F-07 | Корневые плоские слоты `session-hub-windows.json` (`live`, мёртвый адрес) без двойника в `live/` | `session-state` | при откате на фолбэк отдаст мёртвый адрес; `session-hub-linux.json` уже удалён вручную | открыто |
| F-08 | Gate проверен только 23 юнит-кейсами; живого сервера со включённым gate не запускали | `tests/hub-gate-test.js` | T-13/T-16 не подтверждены | открыто |
